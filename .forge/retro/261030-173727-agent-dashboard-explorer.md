- 어긋난 것:
  - 비목표로 둔 레이아웃 작업 두 건을 UAT 중 사용자 요청으로 같은 작업에 넣었다. 가로 스크롤바를 패널 맨 아래에 고정하고, 폭이 모자라면 오케스트레이터 카드를 아이콘과 모델명만 있는 카드로 줄였다.
  - 축소 카드를 72px로 처음 만들었을 때 모델명이 `claude-op…`로 잘려 84px·2줄로 다시 고쳤다.
  - S2는 qa 역할 대신 오케스트레이터가 app.paseo.sh와 chrome-devtools로 직접 했다.

## 배운 것
- 다음엔 다르게:
  - 좁은 위치(사이드바)에 패널을 놓을 때는 가로 스크롤만으로 끝나지 않는다. 사용자는 화면을 보자마자 스크롤바 위치와 축소 모양을 바로 요구했다. 다음에는 계획 단계에서 실제 앱 스크린샷을 먼저 찍어 보여 주고 좁은 폭 동작을 정한다.
  - 폭에 따라 카드를 바꿀 때는 트리를 재지 말고 상수와 깊이로 펼친 폭을 계산한다. 재면 줄인 순간 다시 펴지는 진동이 생긴다.
  - 텍스트가 들어가는 축소 카드는 가장 긴 실제 값(모델 ID)으로 폭을 정한다. 아이콘 폭만 보고 72px로 잡아 한 번 다시 고쳤다.
  - 웹 클라이언트는 `paseo plugin reload` 뒤에 페이지를 새로고침해야 새 패널 위치가 메뉴에 나타난다.
  - 같은 역할의 후속 수정은 새 에이전트 대신 `paseo send`로 기존 에이전트에 이어 맡기면 맥락이 유지되어 빨랐다.
