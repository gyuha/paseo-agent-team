# 2026-10-30 — 새 팀 초안이 프로젝트의 기존 워크스페이스와 겹치지 않는 이름을 받게 한다

## 계획 대비 실제
- 계획대로 된 것
  - S1~S3을 계획대로 끝냈다. 재현 테스트 4개가 red에서 green이 됐고, `npm test` 통과 수가 188에서 192로 늘었다.
  - UAT를 사용자가 통과시켰다. `agent-test-2`에서 New team을 누르면 `orchestrator-2`가 만들어지고 Apply도 성공한다.
- 어긋난 것
  - S1에서 내가 쓴 테스트 기대값이 틀렸다. `Design-2`가 이미 있을 때 기대값을 `Design-3`으로 적었다. 합의한 규칙은 "원래 이름에 `-N`을 붙인다"이므로 결과는 `Design-2-2`가 맞다. 구현은 그대로 두고 테스트를 바로잡았다.
  - 증상을 확인하는 데 질문 두 번(Q1, Q2)이 들었다. 사용자는 처음에 (b) "Apply 후 워크스페이스가 안 생긴다"를 골랐지만, 실제로는 (a) "충돌 오류로 Apply가 꺼진다"였다. 이건 검토 화면 스크린샷을 받고 나서야 확정됐다.

## 배운 것
- 다음엔 다르게
  - "버튼이 안 된다"류 UI 버그는 선택지를 내밀기 전에 막힌 화면의 스크린샷부터 요청한다. 오류 문구 한 줄이 증상 분류 질문 여러 개보다 빠르다.
  - 이름에 번호를 붙이는 규칙을 테스트로 쓸 때는 규칙 문장에서 기대값을 기계적으로 끌어낸다. 직관으로 적은 값(`Design-3`)은 규칙과 어긋날 수 있다.
