Create a project team in Paseo, with one workspace, provider and model for each role and an orchestrator to delegate your requests. Open the Agent team workspace panel or run Create agent team from the Command Center. The sidebar also offers team creation for projects without a team. The Agent dashboard workspace panel shows the project's agents as a tree of agents started by other agents, with status badges, and opens an agent when its card is pressed on hosts that support client navigation.

Requires Paseo 0.13.0 or newer and at least one ready provider on the host. Describe your goal to have a planner propose roles, or start with an empty team. While reviewing, describe a role in a sentence or two and use Add role with AI to have a planner propose one more role. Review the workspace names, models, folders and instructions before pressing Apply. A role can leave its workspace empty to run its sessions in the orchestrator's workspace.

Apply writes `.agents/team.json` in the registered project root, reuses project workspaces with matching titles or creates missing ones, and starts an orchestrator. Applying again tells every running orchestrator in the project to re-read the team. The Agent team panel of any workspace can also start the team there, with every role running as a shared session in that workspace. It then archives the project's plugin-labelled planner agents and unused, otherwise empty Team planner workspaces. Team definitions can be committed to your repository and edited in the panel or file.

The plugin reads project, workspace, agent and provider metadata and the team file. Planning sends your goal, or for one added role your description and the existing role names, workspaces and folders, together with available model IDs to the selected provider, preferring Claude when ready; the planner is instructed to inspect the repository. Orchestrator and role agents send their instructions, prompts and any repository content or tool results they read to their configured providers under those providers' normal behavior. These agents consume provider usage. The plugin has no separate external service or software download.

Role workspaces share the same project checkout. Folder assignments guide agents; they do not enforce filesystem isolation. Avoid overlapping work or ask the orchestrator to sequence it. The planner, orchestrator and role agents start in the provider's reviewed auto mode when it has one: Codex's Auto-review (`auto-review`), otherwise an `auto` mode such as Claude's Auto mode (`auto`). Only a provider with neither uses its unattended mode: the one marked unattended, otherwise the one Paseo marks dangerous, such as Antigravity's Full access. Otherwise they use the default mode. The unattended mode keeps running without asking you; Auto mode and Auto-review route permission requests through an automatic reviewer instead. The planner is instructed not to change files, but is not technically prevented from doing so. Large workspace and agent lists are read as a single page, so existing resources beyond that page can be missed. English and Korean UI text are included.
